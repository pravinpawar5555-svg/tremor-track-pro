- Execution module data lives in public.execution_* tables via src/lib/execution.ts (own small store); daily updates and activity are separate rows per job — keeps multi-day history accurate.
- Manager Dashboard has three views (Management Overview / Customer Success / Execution) in src/components/console/ManagerDashboard.tsx, selected via ?view= on /; it only reads existing stores — engineers keep their own dashboards.
- Manager dashboard action filters/search operate on existing scoped records, with stored deadlines and owners; sections are unframed and no synthetic health score or attendance metric is added — keeps monitoring explainable without changing work rules.
- Report delivery overview uses Monday–Sunday calendar windows and scoped report/schedule data; forecast schedules are labelled not generated and matched by plant/type/due date before counting — keeps next-week monitoring accurate without creating report rows early.
- Engineers → Workload (src/components/console/Workload.tsx) is a read-only planning layer over tasks, reports, visits, comms and execution jobs; levels only appear when public.workload_settings thresholds are set (Settings → Workload) — no scoring from arbitrary numbers.
- Workload day types (Office / Site / Holiday work / Leave / Off) derive in Workload.tsx from visits, job dates, engineer_leaves and non-working days — no attendance records.
- Standalone Execution site visits (factory inspection, sensor collection, etc.) live in public.execution_site_visits via src/lib/execution.ts; they count as Site days in Workload and in the manager Execution view, with an optional related_job_id — avoids fake jobs for non-job visits.
- Approved WFH overrides overlapping leave through workload.ts effectiveLeaves/leaveOn and access.ts dayKind; original requests remain intact, visible leave ranges exclude WFH dates, and holidays/site-work rules stay authoritative — preserves audit history and unrelated leave dates.
- Settings exposes only device notifications to non-managers; permitted devices reconnect in AppShell without requesting permission, and message/ticket push runs after successful cloud saves to avoid lost alerts.
- Engineer monitoring is a manager-only read view over existing summaries and execScope; non-managers retain Workload only, and task-planning indicators are not attendance or online status.
- Plant operational status is independent of category and retained in the main store; lifecycle updates read back before emit and database triggers append history, while ordinary plant edits omit lifecycle fields — prevents stale edits overwriting status, and retains technical/report history without automatic equipment movement.
- Billing deletion is manager-only with explicit confirmation, targets one saved plant/period and checks returned deleted rows before refreshing; plant config and reports are untouched — prevents silent denied deletes and unrelated data loss.
